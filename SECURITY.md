# Security Policy

This policy applies to the **CeoMatheusDev Flax Engine fork**, not to the upstream Flax Engine project.

## Supported versions

Security fixes are handled on a best-effort basis for the default branch and actively maintained branches. This fork does not guarantee support or backports for every upstream release.

## Reporting a vulnerability

**Do not publish exploitable vulnerability details in a public issue, discussion, pull request, or commit.**

Use GitHub's private vulnerability reporting for this repository if the feature is enabled:

[Report a vulnerability privately](https://github.com/CeoMatheusDev/FlaxEngine/security/advisories/new)

If private reporting is unavailable, contact the repository owner through their GitHub profile and request a private channel. Include:

- A concise description and potential impact.
- Affected commit, tag, branch and platform.
- Reproduction steps or a proof of concept, avoiding destructive payloads.
- Any suggested mitigation.

Do not include credentials, personal data, production secrets or unrelated third-party data in the report.

## Scope and upstream coordination

If the issue also affects unmodified Flax Engine, report it privately to the upstream maintainers through the [official Flax contact page](https://flaxengine.com/contact/). Do not assume that a report to this fork reaches the upstream security team.

We will acknowledge reports when practical, investigate them, and coordinate disclosure with the reporter. No fixed response or remediation time is guaranteed.
